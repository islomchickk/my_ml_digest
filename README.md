# Digest

Еженедельный дайджест статей по Data Science, Machine Learning и AI с автоматической отправкой в Telegram.

## Что делает

Каждый понедельник утром бот:

1. **Собирает статьи** из RSS-лент Хабра, Medium и Towards Data Science по темам: ML, AI, NLP, Data Engineering, Data Science, Python, LLM, RAG, MLOps.
2. **Обогащает статистикой** — для первых 50 уникальных статей Хабра в порядке RSS-лент подтягивает рейтинг, просмотры, комментарии и закладки. Лимит задаётся через `HABR_STATS_LIMIT`; остальные статьи тоже участвуют в отборе.
3. **Фильтрует через LLM** — в три последовательных запроса выбирает 5 основных статей, ещё 5 и до 4 дополнительных рекомендаций, пишет саммари на русском.
4. **Отправляет в Telegram** — дайджест с пагинацией и inline-кнопками.

## Источники

| Источник | Темы |
|----------|------|
| Хабр | ML, AI, NLP, Data Engineering, Data Science, Python |
| Medium | ML, LLM, RAG, AI, MLOps, Data Science |
| Towards Data Science | Все публикации |

## Поддерживаемые LLM-провайдеры

- Claude
- OpenAI
- Gemini
- OpenRouter
- NeuralDeep (по умолчанию, OpenAI-совместимый API)

## Быстрый старт

```bash
# Клонируй репозиторий
git clone <repo-url>
cd digest

# Создай .env из примера и заполни ключи
cp .env.example .env

# Запусти вручную
uv run python main.py
```

### Флаги

```
--llm <provider>   LLM-провайдер: claude, openai, gemini, openrouter, neuraldeep
--no-stats         Не собирать статистику Хабра
--dry-run          Не отправлять в Telegram
--no-parse         Пропустить парсинг, загрузить из articles.json
--test-send        Отправить digest_output.json в TG_CHAT_ID (без парсинга и LLM)
--bot              Постоянно принимать запросы дайджеста и нажатия кнопок
--remember-sent    Записать сохранённый дайджест в историю отправок TG_CHAT_ID
```

`digest_output.json` сохраняет оба раздела: `top` и `honorable_mentions`.
Тестовая отправка включает их оба. Для старого файла с массивом основных статей
рекомендации восстанавливаются из `llm_response.txt`, если основные статьи
полностью совпадают. Повторный запрос к LLM не нужен.

Дайджест отображается страницами: продолжение доступно по кнопке «Вперёд».
Кнопки обслуживает постоянно работающий процесс `--bot`; обычная отправка
и `--test-send` завершаются после доставки сообщения.

## Дайджест сейчас

В личном чате отправь боту `/start`: появится кнопка **«📰 Дайджест сейчас»**.
Она также добавляется к каждой странице дайджеста в личке. Кнопка доступна
только пользователю с ID из `TG_CHAT_ID`; канал не получает дайджест по нажатию.

При нажатии бот заново загружает RSS, исключает ссылки из ранее отправленных
основных статей и дополнительных рекомендаций, затем запрашивает LLM.
История ведётся отдельно для каждого чата. Повторные нажатия во время сборки
показывают уведомление; планировщик и кнопка используют общую блокировку.
Обычный еженедельный запуск тоже исключает историю `TG_CHAT_ID` (или канала,
если личный чат не задан).

Если новых статей нет, бот сообщает об этом без вызова LLM. Если их меньше 10,
дайджест содержит доступные статьи. История обновляется только после успешной
доставки; `--dry-run` её не меняет.

В Docker бот автоматически работает в режиме `--bot`. SQLite с историей
и страницами находится в `/app/data/digest.sqlite3`, в томе `digest-data`.
Она сохраняется при пересоздании контейнера. При локальном запуске каталог
по умолчанию — `data/`, его можно изменить через `DIGEST_DATA_DIR`.

Для запуска без Docker:

```bash
uv run python main.py --bot
```

### Обновление с предыдущей версии

Останови прежний ручной polling через `Ctrl+C`. Сохрани уже отправленный
дайджест и ответ LLM перед пересозданием контейнера, затем импортируй их
в историю без повторной отправки:

```bash
docker compose cp digest:/app/digest_output.json ./digest_output.json
docker compose cp digest:/app/llm_response.txt ./llm_response.txt
git pull --ff-only
docker compose up -d --build --force-recreate digest
docker compose restart scheduler
docker compose cp ./digest_output.json digest:/app/digest_output.json
docker compose cp ./llm_response.txt digest:/app/llm_response.txt
docker compose exec digest uv run python main.py --remember-sent
```

После импорта отправь боту `/start` и нажми кнопку. Импорт рассчитан на
последний сохранённый дайджест, который уже был доставлен; более старые
отправки прошлой версии не имели истории.

```bash
docker compose exec digest uv run python main.py
```

## Лимит входа NeuralDeep

Генерация выполняется в три этапа: **5 + 5 + до 4**. После каждого этапа выбранные
статьи удаляются из кандидатов. Следующий системный промпт содержит предыдущий
выбор с саммари и категориями для разнообразия тем и источников. Этот контекст
учитывается в лимите входа и не сокращается вместе с превью кандидатов.
Каждый запрос NeuralDeep имеет собственный лимит выхода 8 000 токенов.
Если кандидатов осталось меньше пяти, используется доступное число; если они
закончились, оставшиеся этапы пропускаются. Отправка начинается после завершения
этапов; ошибка промежуточного запроса не помечает частичный выбор как отправленный.

Перед отправкой NeuralDeep бот оценивает число токенов статей, системного промпта
и JSON-схемы через `tiktoken` (`cl100k_base`). Рабочий бюджет — **45 088** токенов:
лимит тарифа **46 112** минус запас **1 024** на различия токенизаторов и формат API.
Для Qwen это оценка, а не точный подсчёт токенизатором сервера.

Выход NeuralDeep ограничен **8 000** токенов через `max_tokens` в запросе API.
`NEURALDEEP_MAX_OUTPUT_TOKENS` позволяет уменьшить лимит (от 1 до 8 000).
Если модель достигает этого лимита и возвращает `finish_reason=length`,
оборванный ответ сохраняется для диагностики, но не отправляется как дайджест.
Лимит сам по себе не гарантирует завершение JSON-ответа.

Для Qwen рассуждения отключены по умолчанию: `NEURALDEEP_ENABLE_THINKING=false`.
В API передаётся `chat_template_kwargs.enable_thinking=false`; модель отвечает
сразу JSON. Три этапа отбора и формат дайджеста сохраняются, но выбор статей
может отличаться от режима с рассуждениями.
Чтобы включить ограниченные рассуждения, задайте `NEURALDEEP_ENABLE_THINKING=true`
и `NEURALDEEP_THINKING_TOKEN_BUDGET=1024`. Бюджет должен быть положительным и
меньше общего лимита выхода; он не добавляется сверх 8 000 токенов.
По [документации NeuralDeep](https://neuraldeep.ru/llms-full.txt), Qwen игнорирует
`reasoning_effort`, а `chat_template_kwargs.thinking_token_budget` задаёт потолок
рассуждений. Эти параметры ориентированы на Qwen; при смене семейства модели
проверьте поддерживаемые настройки в документации провайдера.
Логи показывают `reasoning_tokens`, если API передаёт этот счётчик, и отдельно
длину рассуждений и ответа в символах. Символы не являются числом токенов.

Запрос сериализуется без отступов. Если он не помещается, бот сначала сокращает
превью всех статей, сохраняя названия, ссылки и статистику. Если даже метаданные
не помещаются, исключает статьи с конца списка. `articles.json` остаётся полным.
Число отправляемых статей и оценка токенов выводятся в лог.

Если API всё же отклоняет запрос с числом входных токенов и лимитом, бот уменьшает
бюджет на основе этих значений и повторяет запрос (не более трёх попыток всего).
Другие ошибки 400 не повторяются. Словарь токенизатора скачивается при сборке
Docker-образа; при локальном запуске — при первом подсчёте.

## Диагностика ответа LLM

Исходный текст ответа сохраняется в `llm_response.txt` до разбора JSON.
Ответы отдельных этапов сохраняются в `llm_response_stage_1.txt` и аналогичных
файлах для этапов 2 и 3; полные ответы API — в соответствующих `.json`.
После успешной генерации `llm_response.txt` содержит объединённый дайджест,
а `llm_response.json` — последний полный ответ API.
Для OpenAI и NeuralDeep полный ответ API сохраняется в `llm_response.json`,
включая `finish_reason`, расход токенов и дополнительные поля провайдера.
Пустой, оборванный или некорректный ответ завершает запуск с понятной ошибкой
без отправки дайджеста. Корректный JSON внутри Markdown-блока или после
закрытого `<think>...</think>` поддерживается.

Для просмотра ответа в контейнере:

```bash
docker compose exec digest cat llm_response.json
```

## Переменные окружения

```env
# Telegram
TG_BOT_TOKEN=         # токен бота
TG_CHAT_ID=           # ID чата для отправки
TG_CHANNEL_ID=        # ID канала (опционально)

# LLM
LLM_PROVIDER=neuraldeep  # claude | openai | gemini | openrouter | neuraldeep
LLM_MODEL=qwen3.6-unlim  # модель (опционально, используется дефолтная)
NEURALDEEP_MAX_OUTPUT_TOKENS=8000  # потолок генерации NeuralDeep
NEURALDEEP_ENABLE_THINKING=false  # Qwen: сразу отвечать без рассуждений
NEURALDEEP_THINKING_TOKEN_BUDGET=1024  # применяется при ENABLE_THINKING=true

# API-ключи (заполни только нужный)
ANTHROPIC_API_KEY=
OPENAI_API_KEY=
GEMINI_API_KEY=
OPENROUTER_API_KEY=
NEURALDEEP_API_KEY=

# Парсер
FETCH_HABR_STATS=true
HABR_STATS_LIMIT=50    # максимум статей для загрузки статистики; 0 отключает её
```
